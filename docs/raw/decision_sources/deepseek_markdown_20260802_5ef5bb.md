### Error 1: Workflow 1 — Parse Intent fails on text messages ("Add STT to Input hasn't been executed")

**Date:** 2026-07-18  
**Workflow:** Workflow 1 (Оркестратор приёма запросов)  
**Symptom:** При отправке текстового (не голосового) сообщения в Telegram Workflow 1 падал с ошибкой:  
`Cannot assign to read only property 'name' of object 'Error: Node 'Add STT to Input' hasn't been executed'`  
Узел `Parse Intent` не мог выполниться.  
**Cause:** В коде узла `Parse Intent` была жёсткая ссылка на узел `Add STT to Input` (`$('Add STT to Input').first().json`), который выполняется только при наличии голосового сообщения. При текстовом сообщении ветка с STT не активировалась, узел не выполнялся, и обращение к нему вызывало ошибку.  
**What was checked:** Проверялись входные данные, работа Groq Intent Classifier, логи n8n.  
**What turned out to be wrong:** Предполагалось, что `Add STT to Input` всегда содержит данные после нормализации, но это не так для текстовых сообщений.  
**Root cause:** Отсутствие проверки на существование узла в контексте выполнения и использование безусловной ссылки на узел из параллельной ветки.  
**Fix:** Замена в коде `Parse Intent` строки `$('Add STT to Input')` на `$('Filter Short Text')`, который выполняется всегда. (Позже это изменение было временно откатано вместе с остальными правками, но признано корректным.)  
**Status:** Resolved (но не применено в боевой версии после отката)

### Error 2: Workflow 2 & 4 — Multiple (costly) calls to DeepSeek analyst due to wrong loop output

**Date:** 2026-07-18  
**Workflow:** Workflow 2 (Поиск частных лиц), Workflow 4 (Поиск тендеров)  
**Symptom:** После импорта исходных workflow наблюдались множественные выполнения Workflow 5 (Scoring Analyst) и списания большого количества токенов DeepSeek за одно задание. Отчёты приходили, но затраты были неоправданно высокими.  
**Cause:** Узел `Execute Workflow`, запускающий аналитик, был подключён к основному выходу `loop` узла `SplitInBatches` (Loop Queries), а не к выходу `done`. В результате аналитик вызывался на каждой итерации цикла поисковых запросов, а не один раз после завершения сбора.  
**What was checked:** Количество execution в Workflow 5, соединения узлов в Workflow 2, параметры вызова.  
**What turned out to be wrong:** Ошибочно предполагалось, что `loop` выход подходит для финального действия; не учитывалось различие выходов SplitInBatches.  
**Root cause:** Неправильное понимание семантики выходов `loop` (текущий элемент) и `done` (после завершения всех элементов) узла SplitInBatches.  
**Fix:** Переключение соединения с выхода `loop` на выход `done`. Для передачи необходимых параметров (job_id, entity_type) добавлен промежуточный узел `Set`, создающий элемент.  
**Status:** Resolved (применено к исходному Workflow 2)

### Error 3: Workflow 5 — "Sheet with name ... not found" when using dynamic sheet name expression

**Date:** 2026-07-18  
**Workflow:** Workflow 5 (Scoring Analyst), Workflow 6 (Report Generator)  
**Symptom:** Узлы Google Sheets (Read Entities, Update Row, Read Qualified Entities) выдавали ошибку: `Sheet with name <expression> not found` или `Sheet with ID ... not found`. Динамическое выражение для выбора листа (leads/companies/tenders) не работало.  
**Cause:** Поле `Sheet` в настройках ноды Google Sheets (режим By Name) не вычисляло JavaScript-выражение, даже если поле было переведено в режим Expression (`fx`). Выражение воспринималось как литеральное имя листа. Аналогично в режиме By ID число воспринималось как текст.  
**What was checked:** Правильность синтаксиса выражения, режимы поля (Fixed/Expression), наличие листов в таблице.  
**What turned out to be wrong:** Предполагалось, что режим Expression в поле Sheet работает для динамического выбора листа, но на версии n8n 2.29.10 это оказалось не так.  
**Root cause:** Несовместимость динамических выражений с полем Sheet в данной версии ноды Google Sheets.  
**Fix:** Полный отказ от динамических выражений. Замена одной ноды с выражением на Switch + несколько статических нод с жёстко выбранным листом из выпадающего списка (By Name).  
**Status:** Resolved (применено в финальной версии Workflow 5 и Workflow 6)

### Error 4: Workflow 5 — "Could not get parameter 'sheetName'" after JSON import

**Date:** 2026-07-18  
**Workflow:** Workflow 5 (Scoring Analyst)  
**Symptom:** При выполнении импортированного JSON узел `Read Leads` (и аналогичные) выдавал ошибку: `Could not get parameter "sheetName"`. В интерфейсе ноды отсутствовало поле Sheet, выбрать лист было невозможно.  
**Cause:** JSON содержал параметр `sheetName` в упрощённом строковом формате (`"sheetName": "leads"`), который не поддерживается нодой Google Sheets v4.5. Нода ожидала объект с полями `mode` и `value` или выбор через UI.  
**What was checked:** Содержимое импортированного JSON, конфигурация узлов.  
**What turned out to be wrong:** Я предоставил некорректный JSON без тестирования в среде клиента.  
**Root cause:** Несоответствие формата параметра `sheetName` ожидаемому структурой ноды.  
**Fix:** Ручное пересоздание узлов Google Sheets с выбором листа из выпадающего списка в интерфейсе n8n.  
**Status:** Resolved (Workflow пересобран вручную)

### Error 5: Workflow 5 — "No columns found in Google Sheets" when using "Map Each Column Manually"

**Date:** 2026-07-18  
**Workflow:** Workflow 5 (Update Row)  
**Symptom:** При выборе режима маппинга "Map Each Column Manually" узел Update Row показывал сообщение "No columns found in Google Sheets. Retry" и не давал выбрать столбцы для обновления.  
**Cause:** Сочетание двух факторов: (1) из-за предыдущих ошибок лист не был корректно определён, и нода не могла загрузить схему; (2) даже при правильном листе схема не загружалась при пустом листе или при отсутствии успешного тестового соединения.  
**What was checked:** Настройки Mapping Column Mode, наличие заголовков в таблице, переключение режимов.  
**What turned out to be wrong:** Ожидалось, что нода сможет загрузить колонки в любом случае, но ей требуется успешное соединение с листом и, возможно, наличие хотя бы одной строки данных.  
**Root cause:** Пустая схема (`schema: []`) и неспособность ноды динамически загрузить структуру без тестового выполнения.  
**Fix:** Временное переключение в режим "Map Automatically", выполнение тестового запуска для загрузки схемы, затем (при необходимости) возврат к "Map Each Column Manually". В финальной версии колонки были прописаны вручную в JSON без необходимости загрузки схемы.  
**Status:** Resolved (ручная настройка маппинга)

### Error 6: Workflow 5 — Trigger Report (Execute Workflow) not firing after loop completion

**Date:** 2026-07-18  
**Workflow:** Workflow 5 (Scoring Analyst)  
**Symptom:** После успешного завершения цикла Loop Entities (все сущности обработаны) узел `Trigger Report (once after all)` не запускал Workflow 6. В логах не было execution для Workflow 6, а сам узел показывал "No output data".  
**Cause:** Выход `done` узла SplitInBatches только сигнализирует о завершении, но не передаёт ни одного элемента данных. Узел Execute Workflow не получал ни одного входного item и поэтому не активировался.  
**What was checked:** Соединения, режим работы Execute Workflow, наличие входных данных на узле.  
**What turned out to be wrong:** Предполагалось, что сигнал `done` эквивалентен передаче пустого элемента, но n8n требует минимум один item для запуска.  
**Root cause:** Непонимание механики запуска подворкфлоу: Execute Workflow запускается только при наличии входных items.  
**Fix:** Добавлен промежуточный узел `Set` (Prepare Report Trigger), который создаёт один элемент с необходимыми параметрами (job_id, entity_type). Выход `done` подключён к этому Set, а Set к Execute Workflow.  
**Status:** Resolved

### Error 7: Workflow 5 — Inverted loop/done connections after manual editing

**Date:** 2026-07-18  
**Workflow:** Workflow 5  
**Symptom:** После ручного восстановления соединений цикл вёл себя неправильно: `done` был подключён к `Rate Limit Wait`, а `loop` к `Prepare Report Trigger`. Workflow не обрабатывал сущности.  
**Cause:** Ошибка при ручном перетаскивании линий во время отладки.  
**What was checked:** Визуальная проверка графа, логи выполнения.  
**What turned out to be wrong:** Визуальное неразличение выходов loop и done при быстром восстановлении.  
**Root cause:** Человеческая ошибка при ручном соединении.  
**Fix:** Удаление неверных соединений и переподключение: верхний выход (loop) к Rate Limit Wait, нижний (done) к Prepare Report Trigger.  
**Status:** Resolved

### Error 8: Workflow 5 — Filter by job_id in Google Sheets returned 0 rows

**Date:** 2026-07-18  
**Workflow:** Workflow 5  
**Symptom:** После добавления фильтра по `job_id` в узлах `Read Leads` (операция getAll с фильтром) нода не находила строки, хотя в листе данные с таким job_id присутствовали.  
**Cause:** Фильтр Google Sheets оказался нестабильным: либо не поддерживал текстовые UUID с дефисами, либо требовал особого формата.  
**What was checked:** Прямой просмотр таблицы, синтаксис фильтра, сравнение с именами колонок.  
**What turned out to be wrong:** Ожидалось, что стандартный фильтр Google Sheets надёжно работает с любыми значениями.  
**Root cause:** Нестабильность встроенного фильтра Google Sheets ноды.  
**Fix:** Убран фильтр из узлов чтения. Вместо этого все строки читаются, а фильтрация выполняется узлом `IF` внутри n8n (Filter by job_id).  
**Status:** Resolved

**Date:** 2026-07-18 (обнаружено при аудите)  
**Workflow:** Workflow 3 (Анализ компании)  
**Symptom:** Если ни URL, ни ИНН не были предоставлены, или одна из веток не выполнялась, узел Merge Sources, ожидающий оба входа, никогда не завершался. Workflow зависал на неопределённое время.

**Fix:** (Предложено) Добавить узлы Set с пустыми значениями на false-выходы IF и подключить их к Merge. После отката к исходным workflow это исправление не было применено и осталось нерешённым.  
**Status:** Unresolved (не исправлено в боевой версии после отката)

## Repeated Mistakes

- **Неправильное использование выходов SplitInBatches (loop vs done).** Проявлялось в Workflow 2, 4, 5. Приводило либо к множественным вызовам, либо к неактивации подворкфлоу. Причина: недостаточное понимание семантики выходов.
- **Динамические выражения в полях Google Sheets.** Попытки использовать выражения для sheetName провалились во всех случаях. Корректное решение — статические ноды.
- **Импорт JSON без тестирования в целевой среде.** Каждый импортированный JSON требовал ручной доработки из-за несовместимости форматов параметров.

## Technical Debt

- **Google Sheets как основное хранилище:** вызывает большинство проблем (лимиты, нестабильность фильтров, невозможность динамических имён). Требуется миграция на БД.
- **Отсутствие версионирования и автоматического обновления ID подворкфлоу:** любое изменение ID требует ручного обновления во всех связанных workflow.
- **Заглушка Throttle Check:** не реализован реальный подсчёт лимитов API, что создаёт риск блокировок.
- **Отсутствие централизованной обработки ошибок API:** большинство нод используют `continueRegularOutput`, маскируя сбои.
- **Автоматизация бэкапов не настроена:** ручное создание бэкапов, нет мониторинга.

## Unresolved Problems

- **Workflow 3 зависание при отсутствии URL/INN.** Предложен фикс, но не применён из-за отката.
- **Workflow 1: ошибка голосовой/текстовой ветки (`Add STT to Input`).** Исправление известно, но не внедрено.
- **Workflow 4: вызов аналитика для найденных тендеров.** Исходно аналитик вызывался только при отсутствии результатов; для реальных тендеров вызов отсутствовал. Статус после отката неизвестен.
- **Throttle Check (Workflow 8) остаётся заглушкой.**
- **Отсутствует механизм повторных попыток (retry) для внешних API.**

## Most Dangerous Issues

1. **Потеря денег из-за множественных вызовов DeepSeek.** (Исправлено переключением на `done` выход.)
2. **Зависание Workflow 3 при неполных входных данных.** Может привести к блокировке ресурса и накоплению незавершённых задач.
3. **Маскирование ошибок через `continueRegularOutput`.** Приводит к записи битых данных в таблицы и неверным результатам, без уведомления администратора.
4. **Нестабильность импорта JSON.** Высокий риск поломки системы при попытке обновления.
