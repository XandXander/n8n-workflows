## 1. crypto is not defined (Task Runner Sandbox)
**Дата:** 28.07.2026  
**Workflow:** OSINT_06 (Create HTML Binary), OSINT_01 (Parse Intent), OSINT_02 (Extract Contacts), OSINT_03 (Build Company Row), OSINT_04 (Parse Tender)  
**Симптом:** `ReferenceError: crypto is not defined` при выполнении Code-узла, workflow останавливается с ошибкой.  
**Причина:** В n8n 2.31.6 Task Runner Sandbox не предоставляет глобальный объект `crypto`. Вызовы `crypto.randomUUID()` или `Buffer.from()` (неявно ссылающийся на `crypto`) приводят к ошибке.  
**Что проверяли:** Все Code-узлы на наличие `crypto`, `Buffer.from`, `$randomUUID()`.  
**Что оказалось неверным:** Предположение, что `crypto` доступен в песочнице, было ошибочным.  
**Root Cause:** Использование `crypto.randomUUID()` и `Buffer.from()` в коде, выполняемом в изолированном окружении Task Runner.  
**Исправление:** Замена `crypto.randomUUID()` на `Date.now().toString(36)+Math.random().toString(36).slice(2,10)`; замена `Buffer.from(html, 'utf8')` на прямую передачу строки в `this.helpers.prepareBinaryData`.  
**Статус:** Исправлено.

## 2. $now.format is not a function
**Дата:** 29.07.2026  
**Workflow:** OSINT_06 (Restore PDF Binary)  
**Симптом:** `TypeError: $now.format is not a function` в Code-узле, генерация PDF останавливается.  
**Причина:** В Code-узлах песочницы недоступен объект `$now`.  
**Что проверяли:** Все Code-узлы на использование `$now.format`.  
**Что оказалось неверным:** Предположение, что `$now` работает в Code-узлах так же, как в выражениях n8n.  
**Root Cause:** Попытка использовать `$now.format(...)` внутри JavaScript-кода.  
**Исправление:** Замена на чистый JavaScript: `new Date().toISOString()` и ручное форматирование даты.  
**Статус:** Исправлено.

## 3. Paired item data is unavailable (потеря контекста после Loop)

**Workflow:** OSINT_04 (Trigger Analyst)  
**Симптом:** `ExpressionError: Paired item data ... is unavailable` при вызове `$('Config').item.json.job_id`.

**Root Cause:** Использование `.item` для доступа к данным узла, расположенного выше по потоку после SplitInBatches.  
**Исправление:** Заменено на `$('Config').first().json.job_id`.  
**Статус:** Исправлено.

## 4. IMAP‑триггер без postProcessAction: "read" (повторная обработка писем)
**Дата:** 29.07.2026  
**Workflow:** OSINT_01  
**Симптом:** Письма обрабатываются многократно, расходуются токены Groq, очередь забивается повторными запусками.

**Root Cause:** Отсутствие `postProcessAction: "read"` в параметрах `emailReadImap`.  
**Исправление:** Добавлен `postProcessAction: "read"`, `customEmailConfig` исправлен на `"[\"UNSEEN\"]"`.  
**Статус:** Исправлено.

## 5. Groq 429 и ретраи, сжигающие квоту
**Дата:** 03.07.2026  
**Workflow:** OSINT_01 (Groq Intent Classifier), OSINT_04 (Groq Tender Relevance)  
**Симптом:** Лимит TPD исчерпан за несколько минут, ошибки 429, сервис недоступен до сброса лимита.  
**Причина:** На нодах был включён `retryOnFail: true` без ограничения количества попыток. При ошибке 429 нода повторяла запрос, каждый раз расходуя токены.  
**Что проверяли:** Логи execution, счётчики использования Groq.  
**Что оказалось неверным:** Ретраи на ошибках лимита не помогают, а только ухудшают ситуацию.  
**Root Cause:** Неправильная стратегия обработки ошибок 429.  
**Исправление:** Отключение `retryOnFail` на всех Groq-нодах; включение `onError: "continueRegularOutput"` с обработкой ошибки в следующем Code-узле.  
**Статус:** Исправлено.

## 7. Двойная сериализация entities (строка вместо объекта)
**Дата:** 29.07.2026  
**Workflow:** OSINT_01 → OSINT_02  
**Симптом:** В Serper уходят запросы с `"услуга"` и `"Россия"`, поиск не находит целевых лидов.  
**Причина:** `Parse Intent` в WF1 сохранял `entities` как строку, затем `Create Job Row` и `Execute Workflow` ещё раз оборачивали её в JSON.stringify. В WF2 парсинг строки давал сбой, и подставлялись дефолтные значения.  
**Что проверяли:** Логи Build Query Matrix (видели `service: "услуга"`), execution WF1 на выходе Parse Intent.  
**Что оказалось неверным:** Предполагалось, что `entities` всегда приходит объектом из LLM.  
**Root Cause:** Отсутствие гарантированного преобразования строки в объект в `Parse Intent`.  
**Исправление:** Добавлен код `if (typeof entities === 'string') { entities = JSON.parse(entities); }` в `Parse Intent`, а также «бронебойный» парсинг в `Build Query Matrix`.  
**Статус:** Исправлено.

## 9. Gotenberg: Invalid form data: form file 'index.html' is required

**Workflow:** Генератор КП (ранний), OSINT_06

**Исправление:** Создан узел `Build Gotenberg HTML Binary` (Code), формирующий бинарный файл `index.html` с MIME `text/html`.  
**Статус:** Исправлено.

# Repeated Mistakes

1. **Использование `site:` в Serper** — дважды в разных workflow (OSINT_02, OSINT_04) до выяснения запрета на бесплатном тарифе.
2. **Отсутствие `Always Output Data`** в узлах чтения Google Sheets — неоднократно приводило к тихим остановкам (OSINT_05 Read Entities, OSINT_06 Read Qualified Entities, OSINT_06 Read Job).
3. **Потеря контекста после Google Sheets** — исходные данные (`job_id`, `chat_id`) терялись после append/update, вызывая пустые входы в последующих узлах.
4. **Неверная настройка IMAP** — сначала отсутствие `postProcessAction`, потом неправильный `customEmailConfig`, потом слишком частый reconnect.
5. **Ретраи на ошибках 429** — проблема повторялась на разных LLM-провайдерах (Groq, DeepSeek), пока не отключили глобально.
6. **Мусорные поисковые запросы** — из-за двойной сериализации entities проблема проявлялась несколько раз, пока не был внедрён гарантированный парсинг в двух местах.

# Technical Debt

1. **Google Sheets как основная шина данных** — работает, но при увеличении нагрузки может потребоваться миграция на PostgreSQL.
2. **Заглушка `Throttle Check` в Utilities** — всегда возвращает `allowed: true`, не выполняет реальной функции.
3. **Отсутствие мониторинга и алертинга** — только Telegram-уведомления администратору, нет системного сбора метрик.
4. **Хардкод адресов и ID** — `xander1s@yandex.ru`, `5640242508`, `1xm1Luua...` в коде вместо переменных окружения.
5. **Код Build Query Matrix** — неоднократно переписывался и содержит следы нескольких подходов.
6. **Смешение Groq и DeepSeek** — часть workflow (STT) всё ещё использует Groq, остальное DeepSeek.
7. **Неполная обработка ошибок** — во многих HTTP-узлах нет проверки на `response.error`.

# Unresolved Problems

1. **Нестабильность Serper** — решено переходом на Tavily, но долгосрочная стратегия поиска не утверждена.
2. **Почтовый канал** — IMAP иногда нестабилен из-за блокировок Яндекса, нет резервного провайдера.
3. **Pinecone host** — захардкожен, при смене индекса потребуется ручная замена во всех узлах.
4. **Backup Pinecone** — не реализован, данные могут быть потеряны.
5. **Скоринг лидов** — порог квалификации (60 баллов) выбран эмпирически, может требовать настройки.

# Most Dangerous Issues

1. **Бесконечный цикл обработки писем** (без `postProcessAction`) — мог за несколько минут исчерпать суточный лимит Groq и заблокировать всю платформу.
2. **Ретраи на 429** — аналогично, быстро сжигали квоту.
3. **Тихий стоп из-за отсутствия Always Output Data** — пользователь не получал отчёт и не знал о проблеме.
4. **Потеря job_id и chat_id при передаче через Google Sheets** — ломала всю цепочку (поиск, аналитику, отправку результата).
5. **Двойная сериализация entities** — превращала поиск в холостой, платформа не выполняла свою основную функцию.
