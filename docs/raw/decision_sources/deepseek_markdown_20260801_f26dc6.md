# Decision: Использование n8n как платформы оркестрации

## Date
Unknown

## Context
Необходимо было быстро разработать модульную систему сбора, анализа и отчётности OSINT-данных с интеграцией множества внешних API, LLM и хранилищ. Требовалась визуальная среда для воркфлоу, встроенные коннекторы и возможность вызова подпроцессов.

## Decision
Выбран n8n (self‑hosted, Docker) в качестве основного движка автоматизации. Вся логика распределена по восьми изолированным рабочим процессам (workflows), взаимодействующим через `Execute Workflow` и общую Google‑таблицу.

## Alternatives Considered
- Разработка на Python/FastAPI с собственным оркестратором.
- Использование облачных решений Make/Zapier.

## Why This Decision Was Made
- Бесплатная self‑hosted версия, полный контроль над данными.
- Богатый набор готовых интеграций (Telegram, Google, HTTP, IMAP).
- Возможность быстро прототипировать и изменять логику без пересборки.
- Поддержка sub‑workflows для модульной архитектуры.

## Trade-offs
**Плюсы:**
- Быстрая разработка и отладка.
- Сообщество и документация.
- Встроенные механизмы обработки ошибок и повторных попыток.

**Минусы:**
- Высокое потребление памяти (Node.js).
- Ограниченная производительность на малых VPS.
- Строгая модель данных, требующая аккуратной работы с выражениями.

## Consequences
Платформа работает стабильно, но требует постоянного мониторинга ресурсов (RAM/CPU) и точного соблюдения правил генерации JSON для успешного деплоя.

## Current Status
Accepted

# Decision: Модульная структура из 8 workflow

## Date
Unknown

## Context
Необходимо было разделить монолитный процесс на независимые этапы: приём запросов, поиск лидов, анализ компаний, тендеры, оценка, генерация отчёта, работа с памятью и утилиты.

## Decision
Создано восемь workflow:
1. Core Router – приём команд из Telegram/Email, классификация, маршрутизация.
2. Search Engine – поиск частных заказчиков.
3. Company Intel – анализ компаний.
4. Tender Intel – поиск тендеров.
5. Analyst – скоринг и обогащение найденных сущностей.
6. Report Generator – генерация Markdown‑отчёта → HTML → PDF, доставка.
7. Pinecone Memory – upsert/query/delete векторных представлений.
8. Utilities – распознавание речи, PDF‑конвертация, логирование, троттлинг.

## Alternatives Considered
- Один монолитный workflow.
- Сервисы на внешнем брокере (Redis Queue).

## Why This Decision Was Made
- Изоляция ошибок: сбой в одном workflow не останавливает остальные.
- Упрощение тестирования и поддержки.
- Возможность независимого масштабирования и переиспользования.

## Trade-offs
**Плюсы:**
- Чёткая ответственность каждого workflow.
- Параллельное выполнение.

**Минусы:**
- Сложность отладки сквозных запросов.
- Необходимость корректной передачи контекста (job_id, entities).

## Consequences
Принята модульная архитектура. Передача данных между workflow осуществляется через `Execute Workflow` с явным маппингом полей. Ошибки в маршрутизации (например, потеря `job_id`) потребовали дополнительных правок.

## Current Status
Accepted

# Decision: Google Sheets как основное хранилище и шина данных

## Date
Unknown

## Context
Требовалось дешёвое, доступное из любого workflow хранилище для задач (jobs), лидов, компаний, тендеров и логов без развёртывания отдельной базы данных.

## Decision
Вся оперативная информация сохраняется в общей Google‑таблице с листами `jobs`, `leads`, `companies`, `tenders`, `reports`, `logs`. Каждый workflow читает/пишет строки через штатную ноду Google Sheets.

## Alternatives Considered
- PostgreSQL напрямую (сложность подключения, миграции).
- Airtable (стоимость, ограничения API).
- Локальный SQLite (проблема разделяемого доступа из разных контейнеров).

## Why This Decision Was Made
- Простота настройки (один OAuth‑токен).
- Удобный визуальный мониторинг.
- Достаточная скорость для текущих объёмов.

## Trade-offs
**Плюсы:**
- Бесплатно, не требует обслуживания.
- Гибкость добавления столбцов.

**Минусы:**
- Rate limits (60 запросов в минуту), риск блокировки при массовых обновлениях.
- Не подходит для высоконагруженных систем.
- Потеря бинарных данных между узлами.

## Consequences
Внедрён паттерн `Always Output Data` для предотвращения остановки workflow при пустых чтениях. На этапе роста нагрузки может потребоваться замена на PostgreSQL.

## Current Status
Accepted

# Decision: Использование векторной памяти Pinecone + Jina embeddings

## Date
Unknown

## Context
Необходимо было исключить дубликаты лидов и обеспечить семантический поиск похожих успешных кейсов для аналитики.

## Decision
Выбран облачный Pinecone (бесплатный стартовый индекс) с размерностью 1024. В качестве эмбеддингов используется сервис Jina AI (`jina-embeddings-v3`, бесплатный тир 1M токенов).

## Alternatives Considered
- ChromaDB локально (доп. нагрузка на VPS).
- Qdrant self‑hosted.
- OpenAI embeddings (стоимость, зависимость).

## Why This Decision Was Made
- Бесплатные лимиты на старте.
- Отсутствие необходимости обслуживать ещё один контейнер.
- Высокое качество эмбеддингов Jina для русского языка.

## Trade-offs
**Плюсы:**
- Мгновенный запуск, нет нагрузки на CPU.
- Хорошая масштабируемость.

**Минусы:**
- Зависимость от внешнего API (латенси, доступность).
- Квоты бесплатного тарифа.

## Consequences
Создан отдельный workflow‑сервис (Pinecone Memory), который централизованно обслуживает операции upsert/query/delete. Все поисковые workflow вызывают его для дедупликации.

## Current Status
Accepted

# Decision: Переход с Groq на DeepSeek как основного LLM‑провайдера

## Date
29.07.2026

## Context
Бесплатные лимиты Groq (100K TPD) быстро исчерпывались, вызывая ошибки 429 и блокировку. Требовалось стабильное, недорогое и качественное решение для классификации, скоринга и генерации отчётов на русском языке.

## Decision
Все вызовы LLM переведены на DeepSeek API (платный аккаунт). Используются две модели:
- `deepseek-v4-flash` – для простых задач (классификация intent, первичная оценка релевантности тендера).
- `deepseek-v4-pro` – для сложного анализа (скоринг лидов, анализ компании, генерация отчёта).

## Alternatives Considered
- Остаться на Groq с платным тарифом.
- Использовать локальный LLM (Ollama) – не хватало ресурсов.
- YandexGPT – неудобный API, сомнительное качество.

## Why This Decision Was Made
- Значительно более высокие лимиты TPD при низкой стоимости.
- Отличное качество русского языка, строгое следование JSON‑формату.
- Разделение моделей «flash/pro» позволило балансировать цена/качество.

## Trade-offs
**Плюсы:**
- Стабильность, предсказуемые расходы.
- Отсутствие борьбы с квотами каждые сутки.

**Минусы:**
- Платный тариф (расходы ~$20–50/мес).
- Необходимость следить за балансом.
- Требование слова «json» в system prompt для JSON mode.

## Consequences
Изменены все HTTP‑ноды: URL `https://api.deepseek.com/v1/chat/completions`, модель заменена. Ретраи отключены. Добавлены обработчики ошибок для поддержания стабильности.

## Current Status
Accepted

# Decision: Генерация PDF через Gotenberg в Docker

## Date
Unknown

## Context
Необходимо было конвертировать аналитические отчёты из HTML в PDF на маломощном VPS без риска утечки памяти.

## Decision
Выбран Gotenberg (Docker‑образ `gotenberg/gotenberg:8`) с ограничением памяти `--memory=512m`. HTTP‑запрос отправляется из n8n на `http://gotenberg:3000/forms/chromium/convert/html` с бинарным файлом `index.html`.

## Alternatives Considered
- Puppeteer/Playwright внутри n8n (OOM риск).
- Внешние API (PDFShift, Api2pdf) – стоимость.
- `wkhtmltopdf` – устаревший рендеринг.

## Why This Decision Was Made
- Полная изоляция Chromium от процесса n8n.
- Бесплатно, безлимитно.
- Гарантированная совместимость HTML/CSS.

## Trade-offs
**Плюсы:**
- Стабильный рендеринг.
- Низкое потребление в idle.

**Минусы:**
- Дополнительный контейнер (~80–512 MB RAM).
- Требуется корректный бинарный файл `index.html` в поле `files`.

## Consequences
Реализован пайплайн: `Markdown → HTML → prepareBinaryData → Gotenberg → Google Drive/Telegram/Email`. Проблемы с именем файла (`index.html`) решены.

## Current Status
Accepted

# Decision: Полный отказ от `crypto`, `Buffer.from`, `$now.format()` в Code‑узлах (Sandbox Safety)

## Date
28.07.2026

## Context
Обновление n8n до версий 2.27+ активировало Task Runner Sandbox, в котором глобальные объекты `crypto`, `Buffer` и метод `$now.format()` недоступны, что приводило к ошибкам `ReferenceError`.

## Decision
Заменить все небезопасные вызовы на sandbox‑safe аналоги:
- `crypto.randomUUID()` → кастомная функция `uuid()` на базе `Math.random`.
- `Buffer.from(html, 'utf8')` → прямая передача строки в `this.helpers.prepareBinaryData`.
- `$now.format(...)` → чистый JavaScript для форматирования дат.

## Alternatives Considered
- Откат n8n (небезопасно).
- Включение `N8N_BLOCK_ENV_ACCESS_IN_NODE=false` (уже было разрешено, но не помогало).

## Why This Decision Was Made
Единственный способ обеспечить совместимость с текущей версией n8n и избежать падений при каждом выполнении.

## Trade-offs
**Плюсы:**
- Абсолютная стабильность Code‑узлов.
- Переносимость между версиями n8n.

**Минусы:**
- UUID менее уникален (коллизии маловероятны, но теоретически возможны).
- Незначительное увеличение кода.

## Consequences
Проведена полная ревизия всех Code‑узлов. Воркфлоу больше не падают с `crypto is not defined`.

## Current Status
Accepted

# Decision: Переход с Serper на Tavily в качестве основного поискового движка для частных заявок

## Date
29.07.2026

## Context
Бесплатный Serper перестал возвращать результаты по большинству целевых запросов (пустые `organic`), несмотря на наличие кредитов. Связано с низким качеством бесплатного API для русского сегмента.

## Decision
Основным источником поиска для `search_private` временно назначен Tavily Search API. Serper оставлен в workflow отключённым для возможного возврата. Все 14 поисковых запросов направляются в Tavily.

## Alternatives Considered
- Google Custom Search API (платно, требует настройки).
- SearXNG (бесплатно, но риск блокировки IP).
- Оставить только Serper – доказал неработоспособность.

## Why This Decision Was Made
- Tavily уже интегрирован, показал лучшие результаты по русскоязычным запросам.
- Бесплатный тариф 1000 запросов/мес, достаточен для тестов.
- Не требует немедленных финансовых вложений.

## Trade-offs
**Плюсы:**
- Стабильная выдача.
- Фильтрация по доменам.

**Минусы:**
- Зависимость от одного провайдера.
- При масштабировании потребуется платный план.

## Consequences
В WF2 добавлен узел `Tavily Search`. Поиск частных заказчиков восстановлен. Дальнейшее развитие предполагает диверсификацию источников.

## Current Status
Accepted (временное решение)

# Decision: Использование Open WebUI и агента `n8n Architect (Pro)` для модификации workflow

## Date
Unknown

## Context
Ручное редактирование JSON‑воркфлоу было медленным и чревато ошибками. Требовался инструмент, позволяющий быстро вносить правки по инструкциям на естественном языке.

## Decision
Настроен Open WebUI с агентом `n8n Architect (Pro)` (модель DeepSeek v4 Pro). Агент получает доступ к инструменту `n8n_workflow_manager` (list, read, write, deploy, sync) и использует набор Skills/Knowledge, накопленный из опыта разработки.

## Alternatives Considered
- Прямые вызовы API n8n через curl/Postman.
- Использование Terraform/Ansible (избыточно).

## Why This Decision Was Made
- Ускорение цикла «задача → исправление → деплой».
- Агент способен проводить массовые замены (например, `$json` → `$('Parse Intent')`), проверять валидность и деплоить.
- Снижение вероятности человеческой ошибки при ручном редактировании JSON.

## Trade-offs
**Плюсы:**
- Высокая скорость внесения изменений.
- Автоматическая валидация и подстановка креденшелов.

**Минусы:**
- Агент может ошибаться (требуется контроль).
- Зависимость от Open WebUI.

## Consequences
Все последние крупные правки (переход на DeepSeek, правка связей, добавление Tavily) выполнялись агентом. Создана база знаний с актуальными правилами n8n.

## Current Status
Accepted

# Major Architectural Decisions

- Модульная архитектура из 8 независимых workflow.
- Google Sheets как центральная шина данных и логов.
- Pinecone + Jina для векторной памяти и дедупликации.
- DeepSeek как основной LLM‑провайдер (flash/pro).
- Gotenberg для генерации PDF в изолированном контейнере.
- Open WebUI с агентом для автоматизации разработки.
- Полный переход на песочнице‑безопасный код (отказ от `crypto`, `Buffer`, `$now`).

# Technology Choices

- **n8n**: выбрана за визуальное программирование, модульность, self‑hosted.
- **Docker**: для унификации окружения, изоляции сервисов.
- **PostgreSQL/pgvector**: используется как штатная база n8n (автоматически).
- **Pinecone**: облачная векторная база с бесплатным стартом.
- **DeepSeek (flash/pro)**: качественный русский LLM с адекватной ценой.
- **Serper, Tavily, Firecrawl**: комбинация поисковых и скрапинговых API.
- **Gotenberg**: конвертация HTML→PDF.
- **Google Sheets**: оперативное хранилище и логи.
- **Jina AI**: эмбеддинги для русского языка.
- **Telegram, IMAP**: каналы приёма команд.
- **Yandex SMTP**: отправка отчётов.
- **Open WebUI**: интерфейс для агента разработки.

# Rejected Approaches

- **Монолитный workflow** – отвергнут из‑за сложности отладки и низкой отказоустойчивости.
- **Локальный Whisper** – не вписался в ресурсы VPS; оставлен облачный Groq Whisper.
- **Полный отказ от Google Sheets в пользу SQLite** – отложен, так как текущих нагрузок хватает.
- **Использование `site:` в Serper** – запрещено на бесплатном тарифе, исключено из запросов.
- **Полный переход на платный Serper** – не оправдал ожиданий по качеству.
- **SearXNG как основной поисковик** – отвергнут из‑за риска блокировок IP, признан резервным.

# Cost vs Quality Decisions

- **Бесплатный Serper против платного Tavily** – качество отдачи победило, временный переход на Tavily.
- **Groq (бесплатный) против DeepSeek (платный)** – DeepSeek выбран ради стабильности и качества.
- **DeepSeek flash vs pro** – flash для простых задач (экономия), pro для аналитики (качество).
- **Gotenberg (локально) vs внешние PDF‑сервисы** – выбрана локальная генерация ради конфиденциальности и нулевой стоимости.
- **Pinecone (облачный стартер) против локального ChromaDB** – Pinecone выбран для простоты и отсутствия нагрузки на VPS.

# Lessons Learned

- Бесплатные API‑ключи ненадёжны для продакшена; всегда нужен запасной провайдер.
- Task Runner Sandbox в новых версиях n8n ломает старые Code‑узлы; необходимо придерживаться sandbox‑safe паттернов.
- Жёсткая типизация выражений n8n (`={{ ... }}`) и проблемы с `item` после циклов требуют постоянного контроля.
- Всегда включать `Always Output Data` в узлах чтения, иначе workflow молча останавливается.
- Агент‑ассистент (Open WebUI) ускоряет разработку, но требует чётких инструкций и верификации.

# Decision Debt

- **Основное хранилище**: при росте нагрузки Google Sheets нужно заменить на реляционную БД.
- **Диверсификация поиска**: Tavily – временное решение, требуется стратегия с несколькими источниками (Google CSE, SearXNG как резерв).
- **Модель DeepSeek**: возможна замена на более дешёвый/быстрый вариант при изменении цен.
- **Мониторинг и алертинг**: отсутствует централизованный сбор метрик, только Telegram‑уведомления.
- **Бэкапы Pinecone**: стратегия резервного копирования векторных данных не утверждена.
