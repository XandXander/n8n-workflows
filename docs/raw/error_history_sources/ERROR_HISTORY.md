# ERROR_HISTORY.md — Журнал регистрации ошибок OSINT-платформы

## 1. Потеря контекста итерации (source_platform & query) в WF2
* **Название:** Сброс контекста (`context.currentItem`) после разделения на батчи в `Extract URLs`.
* **Дата:** Текущий сеанс отладки.
* **Workflow:** `OSINT_02_Search_Engine`
* **Симптом:** Поля `source_platform` получают значение `"unknown"`, а `query` уходит пустым `""`. Из-за этого нарушается связность данных в сквозном логе.
* **Причина:** Использование конструкции `$('Loop Queries').context.currentItem` или метода `$(...).first()?.json` внутри Code-узла JavaScript.
* **Что проверяли:** Проверяли работу метода `.first()?.json` для извлечения данных текущей итерации.
* **Что оказалось неверным:** Метод `.first()` в n8n возвращает самый первый элемент глобального входа (индекс 0) за всё время работы воркфлоу, а при глубокой вложенности после промежуточных HTTP-запросов и вовсе сбрасывает контекст в пустой объект `{}`.
* **Root Cause:** Изменение архитектуры сопоставления элементов (`pairedItem`) и работы контекстов итератора в n8n v1.x/v2.x по сравнению со старыми версиями движка.
* **Исправление:** Замена обращения к контексту на явное получение данных текущего батча через `$(`Loop Queries`).all()?.json`.
* **Статус:** Исправлено.

## 2. Молчаливое падение и прерывание пайплайна в `Extract Contacts`
* **Название:** Остановка воркфлоу из-за `No output data` на этапе парсинга контактов.
* **Дата:** Текущий сеанс отладки.
* **Workflow:** `OSINT_02_Search_Engine`
* **Симптом:** Таблица `leads` в Google Sheets пуста с момента создания. Нода `Append Lead` получает 0 элементов на вход. Пайплайн останавливается, WF5 и WF6 не получают сущностей для анализа.
* **Причина:** Код `Extract Contacts` при отсутствии совпадений по регулярным выражениям или при пустом markdown возвращал пустой массив `[]`, либо падал по `TypeError` при обращении к `cur.url` (так как `cur` из-за ошибки `.first()` был пуст).
* **Что проверяли:** Проверяли условия ветвления `Has Contacts?`, ослабляли фильтры (заменяли AND на OR), добавляли фильтрацию пустышек в `Prepare Context`.
* **Что оказалось неверным:** Ослабление фильтров после ноды не помогало, так как сама нода `Extract Contacts` генерировала пустой вывод (`No output data`), что в n8n по умолчанию означает моментальную остановку текущей ветки выполнения.
* **Root Cause:** Отсутствие гарантированного fallback-объекта (заглушки) в операторе `return` JS-кода при обработке пустых результатов или исключений.
* **Исправление:** Перенос логики по умолчанию внутрь кода ноды. Если контакты не найдены, код принудительно возвращает массив с одним объектом, содержащим флаг `no_results: true` и сохраненные метаданные (`url`, `job_id`, `query`), предотвращая остановку пайплайна.
* **Статус:** Исправлено.

## 3. Коммерческое загрязнение поисковой выдачи на бесплатных лимитах
* **Название:** Нецелевой трафик из-за ограничений базового Serper API.
* **Дата:** Текущий сеанс отладки.
* **Workflow:** `OSINT_02_Search_Engine` (модуль `Build Query Matrix`)
* **Симптом:** На поисковые запросы вида *"нужен монтаж фасада Пермь"* поисковик возвращает исключительно SEO-страницы крупных компаний, подрядчиков и агрегаторов (Авито, Юла, ПульсЦен), а не прямые объявления/заявки от частных клиентов.
* **Причина:** Прямой высокочастотный поиск без операторов сужения выдачи в Google всегда приоритизирует оптимизированные коммерческие сайты.
* **Что проверяли:** Разделение ноды `Build Query Matrix` на клиентские и B2B шаблоны запросов.
* **Что оказалось неверным:** Само по себе изменение текстовых шаблонов (добавление слов "ищу", "требуется") без использования поисковых операторов не способно пробить SEO-выдачу компаний на бесплатном тарифе.
* **Root Cause:** Ограничение алгоритмов ранжирования поисковой выдачи общего назначения при работе с сырыми низкочастотными запросами.
* **Исправление:** Изменение системного промпта генератора запросов в Open WebUI для принудительного внедрения операторов `site:avito.ru`, `site:vk.com` и минус-слов (`-вакансия`, `-подрядчик`), а также проектирование каскадной фильтрации через дешевые токены DeepSeek API для классификации «клиент vs подрядчик».
* **Статус:** В процессе внедрения (архитектурное решение утверждено).

## Repeated Mistakes (Повторяющиеся ошибки)
* **Использование `.first()` для итераций:** Систематическое применение устаревших методов n8n для работы с контекстом внутри циклов `SplitInBatches` / `Loop`, приводящее к потере метаданных (`query`, `job_id`).
* **Прерывание потока через `[]`:** Возврат пустых массивов из кастомных JavaScript-нод, что ломает логику n8n и останавливает выполнение последующих нод (например, `Append Lead`).
* **Избыточное доверие сырому поиску:** Попытка найти сырые лиды через открытый поисковый API без жесткой привязки к конкретным платформам (доскам объявлений) через операторы `site:`.

## Technical Debt (Технический долг)
* **Режим логирования:** Установка параметра `Save Successful: none` в продакшене на этапе активной разработки и отладки платформы. Это полностью скрывает успешные шаги и делает невозможным пост-анализ структуры данных Firecrawl/Serper без принудительного воспроизведения ошибок.
* **Отсутствие валидации схем:** Данные между WF1 (`Core_Router`) и WF2 (`Search_Engine`) передаются без жесткой проверки структуры, что приводит к каскадным падениям (например, `TypeError: Cannot read properties of undefined`) при малейшем изменении ответа сторонних API (Firecrawl).
* **Смешение логики сбора и фильтрации:** Нода `Extract Contacts` одновременно пытается парсить текст, валидировать регулярки и управлять логикой ветвления воркфлоу.

## Unresolved Problems (Нерешенные проблемы)
* **Прямая интеграция с площадками:** Отсутствие выделенных парсеров/шлюзов для Авито, ВК и Юлы. Поиск по ним через Google-индекс (Serper) имеет задержку (лаг индексации) и не гарантирует сбор свежих (сегодняшних) объявлений.
* **Валидация структуры Firecrawl:** Риск изменения структуры ответа во внешней системе скрейпинга (появление новых уровней вложенности в JSON), из-за чего регулярные выражения могут начать обрабатывать `undefined`.

## Most Dangerous Issues (Самые опасные уязвимости и риски)
* **Тихий отказ пайплайна (Silent Failure):** Ситуация, при которой воркфлоу завершается со статусом `Success`, но таблица `leads` остается пустой. Из-за отсутствия алертов в Telegram/Discord о «пустых» результатах команда может неделями не знать о том, что OSINT-платформа ничего не собирает.
* **Память Docker-контейнера при больших батчах:** При обработке тяжелых markdown-страниц от Firecrawl внутри больших циклов (batchSize > 10) на сервере с 6GB RAM без включенного Redis-логирования может произойти падение n8n по ошибке `JavaScript heap out of memory`.
