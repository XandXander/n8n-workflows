## 1. История зарегистрированных ошибок

### Ошибка 1: Синтаксическая порча выражений n8n обратным слэшем
* **Дата:** 24.07.2026
* **Workflow:** Шаблон интеграции Open WebUI RAG -> Справочник нод n8n
* **Симптом:** При импорте сгенерированного моделью воркфлоу в n8n парсер выдавал синтаксическую ошибку на JavaScript-нодах и Telegram-экспрешенах. Воркфлоу не запускался.
* **Причина:** Автоматические парсеры Markdown/LLM принудительно экранировали знак доллара `$` и круглые скобки `()`, превращая их в `\$json` и `\(input.all())`.
* **Что проверяли:** Проверяли валидность экранирования внутри Markdown блоков ` ```json `.
* **Что оказалось неверным:** Предположение, что n8n понимает стандартное Markdown-экранирование спецсимволов. Внутри JSON-строк параметров n8n данные должны быть сырыми.
* **Root Cause:** Конфликт синтаксиса экранирования регулярных выражений LLM-парсёра со строгими правилами кодирования n8n Public API.
* **Исправление:** Удалены все обратные слэши перед системными переменными. В инструкции базы знаний Open WebUI RAG внесен жёсткий запрет: `"text": "={{ \$json.text }}"` и `\$input.all()` должны писаться без экранирования.
* **Статус:** ИСПРАВЛЕНО

### Ошибка 2: Генерация невалидного JSON из-за висячей запятой в плейсхолдере
* **Дата:** 24.07.2026
* **Workflow:** Валидатор ноды `JavaScript Code` (Справочник шаблонов)
* **Симптом:** Ошибка парсинга `SyntaxError: Unexpected token , in JSON at position...` при обработке справочника.
* **Причина:** При попытке очистить захардкоженные координаты ноды из шаблона был удален массив значений, но оставлена запятая: `"position":,`.
* **Что проверяли:** Наличие массива `[300, 600]`.
* **Что оказалось неверным:** Автоматическая замена оставила разделитель структуры JSON пустым, нарушив стандарт RFC 8259.
* **Root Cause:** Человеческий фактор / ошибка генерации кода ассистентом при попытке сделать "динамический плейсхолдер" для вектора позиции.
* **Исправление:** Шаблон переписан с фиксированными эталонными координатами `"position": [300, 600]`, чтобы модель видела рабочий валидный пример.
* **Статус:** ИСПРАВЛЕНО

### Ошибка 3: Обрезание данных IP-адреса хоста в табличной разметке (Data Truncation)
* **Дата:** 24.07.2026
* **Workflow:** Контроль сетевого здоровья `healthcheck.js` (`SERVER_STRUCTURE.md`)
* **Симптом:** Модель получала из базы знаний неверный адрес назначения для проверки хелсчеков и генерировала скрипты на несуществующий IP-хост.
* **Причина:** В процессе рендеринга Markdown-таблицы строка адреса обрезалась на полуслове: `requests http://127.0.0`. Вся часть `:5678/` была потеряна.
* **Что проверяли:** Строку конфигурации сетевых прокси Traefik и n8n.
* **Что оказалось неверным:** Парсинг ячейки таблицы в Open WebUI RAG некорректно обработал двоеточие и обрезал строку по правому краю.
* **Root Cause:** Лимит длины строки при форматировании и отсутствие изоляции сетевых параметров.
* **Исправление:** Строка полностью переписана, обернута в инлайн-код и перенесена из таблицы в маркированный список: `requests http://127.0.0`.
* **Статус:** ИСПРАВЛЕНО

### Ошибка 4: Рассинхронизация версий ядра приложения в документации (Version Mismatch)
* **Дата:** 24.07.2026
* **Workflow:** Сводный аудит инфраструктуры (`ENVIRONMENT.md` vs `SERVER_STRUCTURE.md`)
* **Симптом:** Модель путалась в доступных методах API (Public API v1 vs v2), предлагая устаревшие или несуществующие параметры нод.
* **Причина:** В файле окружения была зафиксирована версия n8n `2.30.7+`, а в файле структуры сервера оставался старый лог контейнера с версией `2.28.6`.
* **Что проверяли:** Теги Docker-образов в конфигурации `docker-compose.yml`.
* **Что оказалось неверным:** Документы обновлялись в разное время, из-за чего база знаний содержала два противоречащих друг другу технических факта.
* **Root Cause:** Отсутствие единого источника правды (Single Source of Truth) для метаданных инфраструктуры.
* **Исправление:** Проведена принудительная синхронизация. Во всех файлах проставлена единая актуальная версия `2.30.7+`.
* **Статус:** ИСПРАВЛЕНО

### Ошибка 5: Утечка и коммит активного токена авторизации (Security Leak)
* **Дата:** 24.07.2026
* **Workflow:** Пайплайн авторизации n8n Public API
* **Симптом:** Прямая компрометация безопасности. Модель имела доступ к строковому значению боевого ключа API.
* **Причина:** В разделе локального окружения Windows и API конфигурации был в открытом виде оставлен действующий ключ `openwebui2`.
* **Что проверяли:** Раздел `API Configuration` и `Local Development Environment`.
* **Что оказалось неверным:** Игнорирование собственного правила безопасности: *«Sensitive values must never be included in prompts sent to external LLMs»*.
* **Root Cause:** Небрежность при составлении логов окружения разработчиком.
* **Исправление:** Значение ключа немедленно вырезано из всех конфигурационных файлов базы знаний Open WebUI и заменено на безопасный токен-заглушку `<REDACTED>`.
* **Статус:** ИСПРАВЛЕНО

## 2. Системный анализ и технический долг

### Повторяющиеся ошибки (Repeated Mistakes)
* **Нарушение структуры JSON при редактировании вручную:** Регулярная порча синтаксиса (запятые, отсутствие кавычек, потеря блоков ` ```json `) при попытке быстро исправить параметры нод n8n.
* **Игнорирование изоляции путей и ссылок:** Пути Windows и Linux (например, `E:\РАБОТА ДОМА...`) регулярно скармливались модели в сыром виде, что приводило к потере экранирования слэшей `\` при парсинге в Open WebUI RAG.

### Технический долг (Technical Debt)
* **Отсутствие автоматизации бэкапов:** В `SERVER_STRUCTURE.md` и `ENVIRONMENT.md` зафиксировано: директория `/opt/beget/n8n/backups` существует, дампы генерируются, но **cron-задачи и скрипты автоматического резервного копирования на сервере отсутствуют**. Бэкап полностью зависит от ручных действий разработчика.
* **Конфликт документации бизнес-логики:** Инфраструктура полностью описана, но логика самих OSINT-сценариев (`PROJECT_KNOWLEDGE.md`) до сих пор не создана. Модель не знает целей и назначения работающих воркфлоу.
* **Отсутствие Watchtower / контейнерного контроля:** Обновление контейнеров n8n, Redis и Postgres происходит вручную, что со временем увеличит разрыв между production и локальной средой разработки.

### Нерешенные проблемы (Unresolved Problems)
* **Потенциальное переполнение RAM/Диска при масштабировании OSINT:** Сервер имеет всего 2 vCPU и 3.8 GB RAM. При одновременном запуске тяжелых OSINT-пауков, вызове Tavily Search и агрегации логов лимит конкурентных исполнений (`Maximum Concurrent Executions = 5`) может намертво подвесить контейнер n8n Worker. Оптимизация под эти лимиты на уровне кода нод еще не проведена.

### Самые опасные уязвимости (Most Dangerous Issues)
* **Параметр доступа к .env из кода:** На сервере установлена переменная `N8N_BLOCK_ENV_ACCESS_IN_NODE=false`. Это означает, что **любая JavaScript-нода имеет полный доступ к системным секретам в файле `.env`**. Если агент Open WebUI сгенерирует или пропустит малварь-код (или произойдет внедрение prompt-injection в анализируемый OSINT-текст), злоумышленник сможет одной строчкой JS-кода выгрузить все пароли от Postgres, Redis и приватные ключи шифрования в Telegram.
